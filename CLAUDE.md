## Current state: empty base
This repo was a boat-racing game. All of it has been removed because Bowling Roll is a new theme. What is left is the base to build on: **the player, the ground, material/texture helpers, physics and the sky**, drawn by a small `main.js`. There is no HUD, no windows, no audio, no networking, no saves and no game rules yet. The old code is not in the tree; it is in git `HEAD` (`git show HEAD:src/<file>`) apart from uncommitted edits made before the cleanup, so check there before rewriting something generic (windows shell, HUD, net, audio, eggs, pets).

Three.js (vanilla, no React) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; `main.js` awaits its init at top level, hence `build.target: 'es2022'`). Everything is procedural (canvas textures); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka (loaded in `index.html`).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel).
- All tunables are in `src/config.js` (the rest of `src/` holds no theme values). It now has: identity (`GAME_SLUG`, `GAME_TITLE`, `DEV_MODE`), the ground (`BEACH`, `WATER`, `SPAWN`, `SPAWN_FACING`), `MODES`, `PHYSICS`, `PLAYER_DIMS`, the look (`RENDER`, `FOG`, `TIME_OF_DAY`, `LIGHT`, `CHARACTER_COLORS`, `MATERIAL_PBR`, `GRAPHICS_PRESETS`, `BLOOM`, `NEON`, `graphicsPreset`), `TOUCH`, `CAMERA`, `SETTINGS`, and the rig (`RIG*`, `PROPORTIONS`, `ANIM`).
- All Bloxity SDK calls go through `src/bloxity.js` and must never throw (SDK may be blocked). It handles init/loading steps, auth (user/guest), settings (`graphics_quality`, `camera_sensitivity`, `show_fps`, `fullscreen`), avatar + proportion change events, the portal `respawn_request` event, the avatar customizer, and the matchmaker helpers the future net layer needs (`resolveServerEndpoint`, `locateRoom`, `updateRoom`).

## Files (`src/`)
- `main.js`: boot order = Bloxity SDK -> renderer (Neutral tone mapping, `RENDER.toneMapping`) -> Rapier -> sky + clouds, lighting, the lego hub (`buildHub` + `buildProps`, which register their own colliders), player body + the player's train (the avatar is a train now; `avatar/` is unused) with chimney smoke and a name tag -> HUD + treadmill tracker -> loop. `__game` (dev only) exposes `player`, `scene`, `renderer`, `camera`, `postfx`, `bodies`, `toggleMode`, `teleport(x, y, z, facing)` (facing `Math.PI` = north, -Z), `state`, `hud`, and `frame(n)` (steps the loop by hand; the in-app browser pane stops drawing while hidden). Dev URL `?at=x,z,facingDeg` starts the train there (screenshots of each side).
- **Player**: `player.js` kinematic capsule + Rapier `KinematicCharacterController` (autostep, slopes, snap-to-ground, pushes dynamic bodies), own gravity/jump (coyote time + buffer). Feet position is `player.position`; `player.renderPosition` is interpolated for drawing. Falling below `PHYSICS.killY` respawns. `camera.js` third-person chase cam (boom, wheel zoom, wall clearance via `segmentClear`, speed FOV) and first person at the inner zoom end; `modes.js` `character` (avatar visible) / `player` (first person, avatar hidden), V toggles. `input.js` keyboard / mouse / pointer lock into `inputState`; `touch.js` + `touch.css` touch controls.
- `avatar/`: `character.js` (player.glb or procedural fallback), `loader.js` (Bloxity cosmetics + proportions from the CDN, `cdn.js`), `rig.js` + `animator.js` (procedural idle/run/airborne/landing; tunables in `ANIM`).
- **Physics**: `physics.js` Rapier world, fixed 60 Hz step with an accumulator; dynamic meshes bound via `bindMesh`/`addDynamic` are interpolated between ticks. Static geometry uses `addFixed` / `addFixedBoxFor`. `segmentClear` is the camera's ray against static colliders only.
- **Hub** (all layout and data in config `LEGO`, `COLORS`, `HUB`, `RAMPS`, `STALLS`, `TREADMILL(S)`, `DISPLAY(_TRAINS)`, `LEADERBOARDS`, `WORLDS_PORTAL`, `PUMPKIN`, `PLAYER_TRAIN`, `START_STATE`, `POWER_GAIN`). Spawn plaza (sand octagon, yellow rim, white pad with the yellow train logo) at the origin; north: the yellow gate into the train lane (`lane.js`), the RedRush / Ironheart ramps, Titles / Railcars stalls; west: the tiered Trains display under the waterfalls; east: the seven treadmills; south: leaderboards in a cliff alcove, the Worlds portal, the pumpkin.
  - `lego.js`: the stud sheet (colour + normal, plain and checker) shared by every `lego(color)` material, `plastic(color)`, metric-UV `boxGeo` / `blk` (y = bottom) / `cbox`, `wedgeGeo`, `slabGeo` (flat outlines, world-metre UVs), `octagon`.
  - `hub.js` `buildHub(scene)`: ground zones, plaza, cliffs (`cliff`: tan bricks, grass lip, vines), plateau + second tier + far grass, trees, gate, lane stub, waterfalls + pool, fences, lamp posts; statics baked. `hubProps.js` `buildProps(scene)`: ramps (+ wind swirls), stalls, treadmills (scrolling belts, zones for game.js), Trains display, leaderboards (canvas boards, placeholder names), Worlds portal (shader), pumpkin, LEVEL sign.
  - `trains.js` `buildTrain(spec)`: steam / diesel / bullet / modern / shunter models facing +Z, `spinWheels`. `signs.js` `sign(lines, height)`: billboard text with icons (`icons.js` paths, shared with the HUD SVGs). `particles.js`: GPU emitters (`parent` option for local smoke).
  - `game.js`: power / level / xp / wins / rebirths / autopilot state (not saved yet), treadmill payouts, `formatNumber`. `hud.js` + `hud.css`: the reference HUD in `--u` units; it moves clear of Boxity's reserved areas and sets `--hud-bottom` / `--hud-top` so `touch.css` keeps the touch buttons off it.
- **Lane** (`lane.js` `buildLane(scene, camera, callbacks)`, config `LANE`): the white studded tunnel north of the gate (green floor, centre track, ceiling just under the far grass, walls cast no shadows so it stays lit), rooms with a treadmill (`buildTreadmill` from hubProps, dir -1) and a once-per-run reward pad, blue blocks narrowing to the next wall. The walls are **stacked spaghetti** (`LANE.stick`: layers of long yellow sticks, ragged ends, baked per wall); `hp` = power to smash through, a weaker train knocks `power` off per ram, is knocked back and the wall jiggles. On a smash every stick becomes a Rapier dynamic body (`LANE.debris`: flung from the impact point, harder the more power beats the wall; capped at `max`, fade after `life`); player.js excludes dynamic bodies from the controller so the train plows through the pile. Juice: hit-stop (`timeScale(realDt)` scales the whole frame's dt in main.js), white burst + floor shockwave rings, CPU particle pools (chips that bounce, dust, additive sparkles, wind arrows past the train), camera shake + FOV punch (`shakeCamera` after the camera update), speed lines on the camera, phone vibration, combos (`comboWindow`; power x combo, sound pitched up, HUD `combo`/`flash`). Inside it `player.speedScale = LANE.speedScale`. Entering it starts an auto-run (`player.autoRun` = heading + a point on the track, `LANE.autoRun`): the train slides onto the centre track and drives itself north at lane speed. Steering anywhere but up the track (WASD / joystick past `release`, read in player.js) hands control back; letting go, or heading up the track, within `snap` m of it steps the train back on and the run resumes (lane.js reads `player.wish`). A wall that holds or a stall stops it, and it waits for a key before auto-running again. The track (`LANE.track`) is at the wheels' gauge; `lane.trackLift(x, z)` raises the drawn train (main.js `railLift`, also wagons and the online pose) onto the rails, and the lane floor's top is flush with its collider (y = 0). Broken walls, pads and sticks reset once the train is back in the hub.

Engine voice by kind (steam: boiler hiss, firebox rumble, distance-spaced accented chuffs that replace `sfx.chuff`; diesel/shunter: pulsed detuned saws rising with load; bullet/modern: motor whine + gear mesh + inverter buzz), wheel roar, rail-joint clack-clacks (`joint`, `wheelbase`; each one bumps the driver), brake + flange squeal, `hiss` on stopping, `horn` on departure (per kind, `hornCooldown`), wind while the driver's head is out. Settings > Train sounds (`trainSfx`) switches the bus.
- **Driver** (`driver.js` `createDriver(trainHolder, { onDepart, onStop })`, config `DRIVER`): the player's Bloxity avatar (player.glb + equipped cosmetics + proportions, reloaded on avatar/proportion changes) at the cab's open side window. Each model in `trains.js` has a hollow cab (`cabBox`: the window cut through both walls, `windowFrame`, `cabInterior` backplate with a flickering firebox or a screen) and `userData.cab` / `userData.kind`. Driven by the train's real motion (lagging "felt" speed -> surge: leans back + pulls the regulator pulling away, pitches forward braking, sways out of curves), joint bounces, engine buzz, breathing, glances. Leans out (+X side, a spring) on departure, on stopping (wave + nod), entering the lane, and every `cruiseLean` s at speed; hips slide to the wall and rise to the sill, waist + chest tilt out, head stays level, hand reaches for the frame. Its legs are hidden (always below the sill). `scene.getObjectByName('driver').userData.api` in dev.
- **Training** (`training.js` `createTraining(scene, playerGroup, train)`, config `TRAINING`): on an unlocked treadmill (`tracker.active`) the train locks onto the belt (`player.training`, honoured in `player.js`: pulled to a spot up-slope of the centre, nose to the headboard) and runs in place, tilted to the slope (`train.rotation.order = 'YXZ'`), wheels spinning, bouncing, thick smoke, white wind streaks past its sides. Steering away from the headboard or jumping lets go (`trainingLetGo`, cleared once off the belt). Payouts pop "+N bolt" at random spots around the train rising far (`hud.pop(..., rise)`) and bump the POWER line (`hud.bumpPower`). ## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
